# EarthSonic — Website Build Specification

This document describes the current EarthSonic website closely enough for another team to recreate its product, interface, behavior, and scientific boundaries. Treat statements marked **Current implementation** as facts about the existing project. Treat statements marked **Future work** as requirements that are not yet implemented.

## 1. Product definition

**Product name:** EarthSonic  
**Primary tagline:** Listen to Our Planet.  
**Supporting line:** Science has a sound.  
**Primary experience:** Listen to an interpretation of NASA's global sea-surface currents and temperature visualization.

EarthSonic gives visitors another way to explore NASA's rendered scientific visualization. It samples color and brightness from the video and maps those visual features into synthesized sound. It does not claim to play a recording of the ocean or to produce original NASA measurements from pixels.

### Non-negotiable scope

- Center the entire site on **NASA Scientific Visualization Studio item #3912, Global Sea Surface Currents and Temperature**.
- Do not add aerosol, air-quality, forest, Arctic, night-lights, or unrelated science stories.
- Keep every page, sound, educational interaction, source link, and image focused on this ocean visualization and the ECCO2 model described by its NASA source.
- Clearly distinguish original model data, NASA's rendered visualization, features calculated from its pixels, and sound generated by EarthSonic.
- Never state that image movement equals current speed, or that a sampled pixel is a calibrated temperature measurement.

## 2. NASA source facts and current data boundary

NASA #3912 visualizes sea-surface current flows from ECCO2. The current paths are colored by corresponding sea-surface temperature. NASA says the underlying model simulates flows throughout the water column, but this visualization uses surface flows.

- NASA SVS record: https://svs.gsfc.nasa.gov/3912/
- Date coverage: **2007-03-25 12:00 UTC through 2008-03-03 12:00 UTC**.
- NASA temperature legend: blue is 0 °C, green is 10–20 °C, yellow is about 25 °C, and red is 32 °C.
- NASA requested credit: **NASA/Goddard Space Flight Center Scientific Visualization Studio**.
- The visualization was produced from ECCO2 model output, a joint MIT/JPL project. NASA describes ECCO2 as synthesizing satellite and in-situ observations using MITgcm.
- NASA's SVS record says it identifies datasets used but does not store the underlying dataset files.

**Current implementation:** video-pixel analysis drives audio. The implementation does not load the original numerical ECCO2 fields. The site's About, Studio, and metadata files must continue to say this plainly.

**Future work:** acquire an appropriately matching ECCO2 Cube92 subset, verify its temporal coverage, variables, units, grid and source citation, then connect verified numerical fields to Studio. ECCO Drive may require a NASA Earthdata account. Do not silently replace the dataset with another ECCO product or combine a different period and call it the NASA #3912 source data.

## 3. Brand and visual system

### Art direction

Create a cinematic ocean-science experience with the calm finish of a premium audio application and the source transparency of a science exhibit. Use generous negative space, clear hierarchy, restrained motion, purposeful imagery, and strong readable controls. The Studio is the product's center of gravity.

Avoid a generic SaaS dashboard, crowded cards, decorative controls that do nothing, excessive glow, neon overload, tiny metadata, and animations that compete with listening.

### Color tokens

Use these tokens consistently:

| Token | Color | Use |
|---|---|---|
| Deep Space | `#080F1E` | Main background |
| Nebula Navy | `#101B30` | Panels and surfaces |
| Cosmic Blue | `#172943` | Secondary surfaces |
| Electric Blue | `#2563EB` | Primary actions |
| Cyan | `#38BDF8` | Focus, active states, ocean controls |
| Violet | `#A78BFA` | Occasional secondary accent |
| Emerald | `#4ADE80` | Status/positive accent |
| White | `#FFFFFF` | Main text |
| Silver | `#CBD5E1` | Supporting text |
| Slate | `#64748B` | Muted labels; check contrast before use |

### Typography

Use Inter for interface copy and a monospace face for dates, sample IDs, source metadata, and audio readouts. The current app loads Inter and DM Mono; a recreation may use JetBrains Mono if that is part of the selected design system. Keep body copy around 16–18 px and secondary copy 14–16 px. Small scientific labels must remain legible and must not carry essential meaning by themselves.

### Layout and motion

- Desktop content max width is about 1240 px.
- Use a persistent top navigation, page-level content container, and consistent footer.
- Studio uses a two-column media/analysis layout on wide screens and stacks into one column on mobile.
- Explore uses the globe and selected-story panel as an ocean exploration aid, not a map of measured local values.
- Respect `prefers-reduced-motion` and the user's in-app reduced-motion preference.

## 4. Site map and shared shell

Implement six connected routes:

1. `/` — Home
2. `/explore` — Explore
3. `/studio` — Sonification Studio
4. `/earth-radio` — Earth Radio
5. `/discover` — Discover
6. `/about` — About

Use a shared shell with a brand link, mobile navigation toggle, primary route links, Accessibility control, persistent audio mini-player, skip navigation, and footer. Unknown paths should show a clear not-found page.

The navigation summary text should describe the current route for speech output. The brand mark is a simple waveform symbol and the word EARTHSONIC; do not add NASA logos or mission marks.

## 5. Page specifications

### 5.1 Home

**Purpose:** Immediately explain the ocean-focused sonification and send visitors into Explore or the listening experience.

**Hero:**

- Eyebrow: NASA SVS #3912 and ocean sonification.
- Large question headline: “WHAT DOES OUR OCEAN SOUND LIKE?”
- Short copy explains that this is NASA's global sea-surface currents and temperature visualization, and that EarthSonic's audio comes from rendered video features.
- Primary action: Explore the ocean.
- Secondary action: jump to the “How it works” explanation.
- Visual: spherical/cinematic treatment of NASA #3912 imagery, subtle orbit/ripple decoration, and a quiet coordinate or source label. The visual is decorative context, not a scientific map or a new data layer.

**Sections, in order:**

1. A concise introduction to visual patterns as another way to learn.
2. One featured experience card for #3912, with source credit and open-in-Studio link.
3. Three short benefit blocks: see the science, hear patterns, understand the mapping.
4. Four-step process: **VISUALIZE → ANALYZE → TRANSLATE → LISTEN**.
5. Accessibility section with audio-first explanation and browser speech preview control.
6. Final call to action into Explore.

Do not call the current output “data-driven sound” without qualifying that it uses rendered pixels. The speech preview is browser speech synthesis, not a NASA recording or AI-generated voice.

### 5.2 Explore

**Purpose:** Provide a focused, searchable entry point to the one ocean visualization.

- Ocean-specific hero, naming NASA SVS #3912 and ECCO2 surface-current flows colored by temperature.
- Interactive Three.js globe uses the locally packaged #3912 still as its texture.
- Offer three ocean-region entry points: North Atlantic, North Pacific, Southern Ocean. These markers only select an area/topic in the interface. They are not localized model measurements.
- Globe interaction: drag to rotate, wheel to zoom, arrow keys to rotate, plus/minus to zoom, region buttons for keyboard-accessible selection, and marker click where available.
- If WebGL or the texture fails, show an illustrated/static fallback and state that the NASA image is unavailable.
- A searchable story card gives title, context, date coverage, credit, open-in-Studio action, and direct NASA source link.
- Search should filter the one story and show a useful empty state. Avoid catalog sorting and category filters that imply multiple unrelated datasets.

### 5.3 Sonification Studio

**Purpose:** Demonstrate and explain the conversion from a NASA video frame to sound. This is the primary feature page.

#### Desktop layout

- Header with Studio title, a concise description, and the one NASA story selection (or display it as a fixed story label if no selector is needed).
- Left/main column: NASA video, video timeline, frame controls, speed, fullscreen, date span, data-basis label, provider credit, NASA source link.
- Right column: live image-feature profile and mapping preview.
- Beneath these: controls for pitch span, pulse sensitivity, sound intensity, and stereo width; then audio listen panel with presets, volume, mute, and animated frequency/waveform visualizers.
- A source-transparency section explains documented variables, NASA temperature legend, image-derived mappings, and scientific limits.

#### Video interactions

- Use the packaged NASA WebM. Native HTML video controls provide the basic accessible playback affordances.
- Add previous/next frame buttons, changing the video position by approximately `1/30` second per action.
- Add seek slider, playback-rate selector (`0.5×`, `0.75×`, `1×`, `1.25×`, `1.5×`, `2×`), and fullscreen toggle.
- Keep audio synchronized when starting or pausing the generated sound. Stop or pause at the video end.
- Sample a fresh frame after seek and on video playback updates.
- Handle media errors with a visible status, an explanation, and a direct NASA source link.

#### Frame-analysis pipeline

1. Read the current HTML video frame into a hidden Canvas.
2. Downsample to **96 × 48 pixels**; do not retain or upload frames.
3. Read RGBA pixels locally. If Canvas access fails, show an explicit error; do not invent replacement values.
4. Calculate normalized and descriptive visual features:
   - Average luma/brightness using `0.2126R + 0.7152G + 0.0722B`.
   - Average RGB channels (0–255).
   - Three most common coarse color bins; each RGB channel is placed into one of four buckets.
   - Average brightness in the northwest, northeast, southwest, and southeast quadrants.
   - Warm/cool balance derived from mean red and blue values.
   - Spatial detail from neighboring-pixel luma differences.
   - Left/right brightness balance.
   - Change since the previous sample using average RGB difference.
5. Throttle normal playback sampling to roughly one sample every 240 ms. Force a sample after a seek or initial frame load.
6. Label sample number as the **analysis sample index**, not the encoded frame number.
7. Label all measurements as rendered-pixel properties. No current speed or calibrated local temperature is calculated.

#### Current sound mapping

Normalize the image features into stable ranges and smooth control updates:

| Rendered image feature | Sound control | Current range/behavior |
|---|---|---|
| Warm/cool color balance | Tone frequency | 170–520 Hz by default; pitch-span control changes the upper range |
| Change between sampled frames | Pulse density | 0.5–5 Hz base, adjusted by pulse sensitivity |
| Average luma/brightness | Mapping gain | 0.30–0.85 base, adjusted by intensity |
| Left/right brightness balance | Stereo pan | −0.75 to +0.75, adjusted by stereo width |

These relationships are artistic translations of the rendered image. They are not a direct decoding of ECCO2 fields. Do not describe the pulse as ocean-current speed or the pitch as an exact temperature.

#### Audio engine and controls

- Use Web Audio API oscillators, gain nodes, a filter, stereo panner, analyser, and volume node.
- Start audio only following an explicit user action to comply with browser autoplay policies.
- Presets: Ambient, Piano-style, Electronic, Minimal. Presets change oscillator timbre/filtering only; the feature-to-sound mapping stays the same.
- Include play/pause sonification, volume, mute, current mapped values, spectrum, and waveform visualization.
- Expose active state with clear labels such as “Pause sonification” and “Now listening.” Show errors if the audio context or source media cannot start.
- Persist the shared player state so playback can continue across route changes where appropriate.

### 5.4 Earth Radio

**Purpose:** Offer a continuous listening view for the same #3912 ocean visualization, not a general music service.

- One station: **Currents & temperature**, in **Ocean Radio**.
- Station artwork is the local NASA #3912 still. Display the same time coverage, NASA credit, source link, and image-derived mapping note.
- Load the source video/frame on explicit “Load” action; do not eagerly download it on page entry.
- Player: play/pause generated sound, previous/next station controls (with one station they cycle back to the same station), seek, elapsed/total time, and volume.
- Favorites and playlists are local to the browser and stored in localStorage. Include create-playlist and add-current-station actions with status announcements.
- Persistent mini-player remains available after starting a track.
- Explain that the sound is generated from sampled video frames; do not add unrelated prerecorded music.

### 5.5 Discover

**Purpose:** Teach the user to listen for the mapping and answer grounded questions.

#### Guess the Ocean

- Prepare the NASA video/clue only when requested.
- Play a 10-second generated clue based on #3912 frame samples.
- Ask: “What controls the pitch?” Current answers identify rendered warm/cool color balance, frame-to-frame image change, or neither.
- Allow answer selection only after the clue has played or been paused; show correct answer and mapping explanation.
- Persist score locally in the browser. Include retry/replay and source links.
- State that the clue follows rendered pixels rather than direct measurements.

#### Earth Interpreter

- This is a deterministic local explanation helper, **not an AI service**.
- Suggested question chips cover the sound mapping, pitch, color legend, selected region, and a simple explanation.
- A text field accepts a question; answer logic uses keyword groups to choose a source-grounded response about the configured NASA record.
- Attach a NASA #3912 source link to responses. Do not invent regional values or live observations.

#### Science context

Show the title, category, period, short NASA description, one documented-variable note, and source link. Teach only information supported by NASA #3912/ECCO2 source material and explain limits plainly.

### 5.6 About

Include:

- The access problem: visual-only science can exclude blind/low-vision visitors and can hide temporal patterns.
- The approach: a second, audio channel for one ocean visualization.
- A seven-step diagram/list: NASA source → frame capture → visual analysis → normalization → sound mapping → audio synthesis → listening and comparison.
- Technology stack: React, TypeScript, Vite, Canvas API, Web Audio API, Three.js, NASA SVS, Tailwind CSS.
- Integrity explanation separating original measurements, rendered pixels, derived image features, and generated audio.
- Exact source credit and NASA link.
- Accessibility feature list.
- Explicit note that numerical ECCO2 fields are not currently integrated.

## 6. Shared accessibility requirements

- Semantic landmarks, heading hierarchy, descriptive page titles, skip navigation, associated labels, and meaningful button/link names.
- Keyboard operation for navigation, globe region buttons, video controls, audio controls, quiz, and interpreter.
- Clear visible focus ring with a cyan outline and sufficient separation from the background.
- No information conveyed by color alone; pair charts/color samples with text values.
- Screen-reader labels for video, sliders, meters, status changes, and audio visualizers. Keep decorative visuals `aria-hidden`.
- High-contrast mode, reduced-motion mode, adjustable text scale (100–130%), spoken page summary via browser speech synthesis, and Close Your Eyes Mode.
- Close Your Eyes Mode reduces decorative imagery while retaining the content, controls, and source explanations.
- Keyboard shortcuts: `Alt+Shift+A` opens/closes accessibility settings; `Space` toggles the active soundscape; `M` toggles mute; `Escape` closes navigation/settings. Avoid intercepting shortcuts while a text field, button, or link is focused.
- Use polite live regions for loading, playback, error, quiz, and interpreter states.
- Aim for WCAG 2.2 AA; run keyboard and screen-reader checks before release.

## 7. Technical structure

Keep scientific processing separate from presentation. A suitable module layout is:

```text
src/
  audio/                 Web Audio engine, shared audio state, visualizers
  components/layout/     Header, footer, page containers
  components/earth/      Experience card and interactive globe
  data/                  One NASA dataset and one ocean experience/station
  pages/                 Home, Explore, Studio, Earth Radio, Discover, About
  services/              Frame analysis, normalization, sonification mapping
  styles/                Design tokens, global styles, readability overrides
public/nasa/ocean-currents/
  videos/                 Local NASA WebM
  images/                 NASA still and color legend
  metadata/               Source record metadata JSON
  documentation/          Asset provenance and scientific limitations
```

Use typed interfaces for dataset metadata, frame metrics, audio controls, and station/playback state. Centralize the one dataset configuration so every route shares the same title, source, media, credit, period, legend, limitations, and mapping.

### Current local NASA assets

- `public/nasa/ocean-currents/videos/ecco2_sst_flow.webmhd.webm` — NASA 960 × 540 assembled WebM.
- `public/nasa/ocean-currents/images/global_ecco2_temperature_currents.jpg` — NASA #3912 still image.
- `public/nasa/ocean-currents/images/sst_ecco2_colorbar.png` — NASA temperature legend.
- `public/nasa/ocean-currents/metadata/nasa-svs-3912.json` — source facts, dates, legend, credit, asset URLs, and data-status note.
- `public/nasa/ocean-currents/documentation/README.txt` — provenance, credits, limitations, and numerical-data status.

Do not preload thousands of frame images. Use the compact video and draw only the current frame to Canvas. Keep audio nodes, animation frames, event listeners, and video state cleaned up on unmount.

## 8. Error states and resilience

- Video fails: show a plain-language error, a retry if supported, and an external NASA source link.
- Canvas sampling fails: identify that playback may work while pixel access is blocked; do not fabricate metrics.
- Audio is blocked: show a user-action/browser-audio message; never start sound without user input.
- WebGL is unavailable: show a static/illustrated globe fallback and retain region buttons.
- localStorage fails: keep the feature usable for the current session and announce that saving is unavailable only when it matters.
- Empty search: preserve the query and explain how to clear/change it.
- Every visible control must change the state it describes or be removed.

## 9. Build and quality checklist

1. Install dependencies and run the Vite development server.
2. Run `npm run build` and fix TypeScript/build issues.
3. Open every route and verify the single NASA source is used everywhere.
4. Confirm the local video, poster, colorbar, and metadata URLs load.
5. In Studio, play/pause/seek/step/change speed/fullscreen; confirm frame sampling updates; start sonification and confirm the audio controls and visualizers respond.
6. Check audio mapping sliders and verify that presets change timbre only.
7. Check Earth Radio load/play/seek/volume/favorite/playlist behavior.
8. Check quiz timing/scoring, interpreter answers, and NASA source links.
9. Use the entire app with keyboard only; check focus, spoken states, contrast, motion preference, text scale, and small screens.
10. Test media/network failure and WebGL fallback.
11. Confirm that no copy presents pixel features as model measurements.
12. Before challenge submission, publish the site, prepare a public demo of at most 7 slides or 30 seconds, and complete NASA/source/resource and AI-use disclosures.
